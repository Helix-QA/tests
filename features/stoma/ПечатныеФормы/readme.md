## Назначение
Авто-тест предназначен для комплексной проверки формирования печатных форм в медицинской информационной системе. В ходе выполнения сценария автоматически подготавливаются тестовые данные, создаются необходимые документы, выполняется проверка печатных форм по эталонным шаблонам, а также тестируется возможность изменения пользовательских макетов печати.

## Что выполняет авто-тест
### 1. Подготовка тестового окружения

* очищает ранее созданные переменные;
* загружает тестовые данные;
* создаёт необходимые переменные;
* создаёт ответственных сотрудников;
* создаёт услуги для дальнейшего использования в документах.

### 2. Заполнение данных клиники
Автоматически заполняет реквизиты структурной единицы:

* контактные данные;
* адрес;
* телефон и электронную почту;
* координаты;
* страну и валюту.

### 3. Заполнение данных организации
Заполняет реквизиты организации:

* ИНН;
* ОГРН;
* ОКПО;
* ОКАТО;
* ответственных лиц (руководитель, главный бухгалтер, кассир, главный врач, кладовщик).

### 4. Создание приёма пациента
Создаёт документ «Приём»:

* выбирает пациента;
* добавляет медицинскую услугу;
* проводит документ;
* сохраняет ссылку на созданный приём для использования в последующих сценариях.

### 5. Проверка печатных форм документа «Приём»
Проверяет корректность формирования следующих печатных форм:

* Акт о выполненных работах;
* Акт о выполненных работах (без сумм);
* Гарантийный талон;
* Консультация врача;
* Талон амбулаторного пациента.

Каждая печатная форма сравнивается с эталонным шаблоном (`.mxl`).

### 6. Проверка пользовательских макетов печати
Для печатных форм:
* «Акт о выполненных работах»;
* «Акт о выполненных работах (без сумм)»

авто-тест:
* открывает инструменты администратора;
* изменяет макет печатной формы;
* сохраняет изменения;
* повторно формирует печатную форму;
* проверяет, что изменения корректно отображаются;
* восстанавливает стандартный макет после завершения проверки.

### 7. Проверка оплаты
Выполняет:
* оплату приёма;
* возврат оплаты;
* повторную оплату.

После этого используются созданные финансовые документы для проверки печатных форм.

### 8. Проверка финансовых документов
Проверяет печатные формы:
* Приходный кассовый ордер;
* Акт о возврате денежных средств.

### 9. Проверка медицинских карт
Изменяет вид медицинской карты пациента и проверяет формирование следующих печатных форм:
* Амбулаторная карта 043/У А4;
* Амбулаторная карта 043/У А5;
* Медицинская карта 025У/04 А5;
* Медицинская карта 025У/14;
* Медицинская карта 025У/25;
* Амбулаторная карта 043 СССР А4;
* Амбулаторная карта 043 СССР А5.

### 10. Проверка складских документов
Создаются и проверяются документы:
* Поступление запасов и услуг;
* Реализация;
* Списание запасов;
* Заказ поставщику.

Для них проверяются печатные формы:
* Товарная накладная (ТОРГ-12);
* Расходная накладная;
* Акт о выполненных работах;
* Универсальный передаточный документ (УПД);
* Требование-накладная (М-27);
* Акт о списании запасов;
* Заказ поставщику.

### 11. Проверка плана лечения
Создаётся документ «План лечения», после чего проверяются печатные формы:
* План лечения (медицинский);
* План лечения (финансовый);
* Комплексный план лечения (медицинский);
* Комплексный план лечения (финансовый).

### 12. Проверка справки в налоговую
Авто-тест:
* создаёт приём с необходимыми услугами;
* выполняет оплату;
* создаёт документ «Справка в налоговую»;
* заполняет суммы по кодам расходов;
* формирует печатную форму;
* проверяет соответствие эталонному шаблону;
* дополнительно проверяет наличие QR-кода.

### 13. Очистка тестовых данных
После завершения всех проверок авто-тест:
* очищает заполненные реквизиты структурной единицы;
* очищает реквизиты организации;
* восстанавливает стандартные макеты печатных форм.

## Результат выполнения
После успешного выполнения сценария подтверждается:
* корректное заполнение необходимых данных;
* успешное создание и проведение документов;
* корректное формирование всех проверяемых печатных форм;
* корректная работа пользовательских макетов печати;
* соответствие печатных форм эталонным шаблонам;
* восстановление исходного состояния системы после завершения тестирования.
